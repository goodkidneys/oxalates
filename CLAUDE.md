# Working on this repository

This is a private static site (GitHub Pages) that serves as a vegan low-oxalate diet reference.
Plain HTML/CSS/JS, no build step, no dependencies. `index.html` + `styles.css` + `app.js` are the
app; everything under `data/` is content.

## Non-negotiables

- Keep `data/*.js` in their canonical format: a header comment, then
  `const X_META = {...};`, a blank line, then `const X_DB = [...];` with pure JSON inside. The in-app
  GitHub publisher and `tools/validate.js` parse them with a regex + `JSON.parse`. Do not add
  comments or trailing commas inside the JSON, and do not rename the constants.
- Keep the site un-indexable: the `robots` meta tags in `index.html` and `robots.txt` stay.
- Run `node tools/validate.js` before every commit that touches `data/`. It must report 0 errors.
- Never fabricate an oxalate value. Every number needs a source in `source` (and a note when
  sources disagree). If a value is an estimate or unmeasured, say so in `source`/`notes` and set
  `disputed: true` when sources conflict.
- Record every value change in `data/changelog.js` (newest release first; add a release object with
  `date`, `title`, `summary`, `changes: [{id, field, before, after, why}]`).

## Data schema

### `data/foods.js` (curated list, ~250 vegan foods)

```
{ id, name, aliases[], category, serving, servingGrams|null, oxalateMg (display string; may be a
  range like "23–48" or "~55"), oxalateNum (number used for math and sorting), riskLevel
  (LOW | MODERATE | HIGH | VERY HIGH | LOW–MOD), measured (Harvard directly measured), starred
  (classification changed with newer data), disputed, source, notes, preparation, swapTo[],
  replaces[], calciumInfo|null, nutrition|null (per 100 g: kcal, protein, fat, carbs, fiber, calcium) }
```

- `category` must be one of `FOODS_META.categories`.
- Risk thresholds per listed serving: ≤10 LOW, 11–25 MODERATE, 26–99 HIGH, ≥100 VERY HIGH.
- `servingGrams` is the weight of the listed serving; the recipe builder needs it to convert cups,
  grams and ounces. `nutrition` is per 100 g from USDA FoodData Central (approximate).
- Aliases are search synonyms (UK/US names, plurals are handled automatically).
- Bump `FOODS_META.count` and `lastUpdated`.

### `data/harvard.js`

Generated by `tools/harvard_xlsx_to_js.py` from the Harvard spreadsheet in `docs/`. Do not hand-edit;
regenerate. Rows: `{ id: "h001", group, item, serving, mg, measured }`.

### `data/recipes.js`

See `RECIPE_TEMPLATE.md`. Ingredient `foodId` must exist in `foods.js`; `harvardId` in `harvard.js`.
Per-serving risk thresholds: ≤10 LOW, ≤25 MODERATE, ≤50 HIGH, else VERY HIGH. Bump
`RECIPES_META.count` and `lastUpdated`.

## Common tasks

**Add a recipe from pasted JSON (produced by the site's Recipe Builder):** append the object to
`RECIPES_DB`, bump meta, validate, commit "Add recipe: <name>", push.

**Add a recipe from a URL or rough text:** extract name, servings, times, ingredients, steps. For each
ingredient find the best `foods.js` entry (or Harvard row), convert the amount to a multiple of the
listed serving or to grams via `servingGrams`, and compute `oxalateMg = factor × oxalateNum`. Compute
nutrition per serving from `nutrition` × grams/100 when weights are known; otherwise mark
`nutritionSource: "estimated"`. Write honest `oxalateNotes` naming the dominant ingredient and the
calcium pairing. Set `oxalateSource` to `FOODS_DB`, `HARVARD`, `manual` or `estimated` per ingredient.

**Add or correct a food:** add to `FOODS_DB` with all fields (use `null`/`[]` where unknown), cite the
source, add aliases, nutrition and `servingGrams` if you can. Log the change in `changelog.js`.

**Check for data updates online (do this every few months or when asked):**
1. Harvard table: is there a file newer than Nov 2023? Landing page
   https://hsph.harvard.edu/department/nutrition/nutrition-questionnaire-service-center/ ; current file
   https://hsph.harvard.edu/wp-content/uploads/2024/07/OXALATE-TABLE-1.xlsx . If newer, download to
   `docs/`, run the converter, diff, and reconcile curated values whose `source` is "Harvard 2023".
2. OHF list: https://ohf.org/oxalate-food-content-database/ (PDF was dated 2024-02-27).
3. PubMed / journals for new oxalate assays of plant foods (search terms: "oxalate content" plus
   plant milk, tofu, tempeh, pea protein, plant-based meat, chia, seitan, matcha, flour).
4. Guidelines: AUA medical management of kidney stones (2026), EAU urolithiasis (annual), NKF pages.
5. Write the report to `docs/research/YYYY-MM-DD-oxalate-data-check.md`, apply value changes with
   `disputed`/`notes` where sources conflict, log them in `changelog.js`, and update the "Research
   check log" section of `index.html` (Sources view) and, if guidance changed, the Guide view.
   The previous report (2026-09-25) is the model to follow.

## Checks before pushing

```
node tools/validate.js
node --check app.js
```

Optionally smoke-test in a browser: `python3 -m http.server 8000` then open
http://localhost:8000/#/search/lentil and http://localhost:8000/#/builder.

## Deployment

GitHub Pages serves `main` at https://goodkidneys.github.io/oxalates/ (enable once under Settings →
Pages → Deploy from a branch → main / root). Pushing to `main` deploys; there is no build.
